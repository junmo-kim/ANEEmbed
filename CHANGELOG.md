# Changelog

## v0.1.0

First release. EmbeddingGemma 2 text and image embeddings on the Apple Neural Engine from one Swift binary with no third-party dependencies: the OpenAI-compatible `/v1/embeddings` server, MCP over stdio and HTTP, and the `embed`, `similarity`, `tokenize`, `doctor`, `models` and `bench` commands. Nothing runs on the GPU.

Model layout "layoutR" (model package `manifest_version` 2; an older package is rejected with a message saying so). Texts up to 1280 tokens are packed into fixed-shape bucket calls (`embed_64` … `embed_1280`), texts of 1281–2048 tokens into windowed packing functions (`winp1536`, `winp2048`), and with `--max-tokens` up to 8192 each longer text runs in one windowed call (`winl3072` … `winl8192`). Concurrent short requests, images included, are coalesced into shared calls, and the calls of one request run at most three at a time, so host memory does not grow with the size of a batch. Cached starts load functions four at a time. Images use the official 280-token preprocessing, bit-exact against Hugging Face. On an M5 Ultra a short query takes 3.4 ms, a 2048-token text 168 ms and an 8192-token text 1.19 s; on an M4 a short query takes 5.0 ms, a 2048-token text 210 ms and a request of 10 texts of 2048 tokens 2.09 s. Accuracy against the original fp32 model over HTTP on public data: cosine ≥ 0.99990 (median 0.999975) for text up to 8192 tokens and for images. The Neural Engine's working buffers take 5.3 GB at the default settings and 13.3 GB with `--max-tokens 8192`; they are wired only while in use and purgeable when idle.

Models and self-test. `models install` downloads the pinned model package (or `--from` a local copy), checks every file's SHA-256, compiles it on the Mac and runs the package's self-test. Only functions that pass the self-test in this run serve (an allowlist): a function the package has no test for, or whose output has a NaN or an infinity, is not served; a package without readable self-test data or a complete `manifest.json` does not load, unless `--selftest skip` (`ANEEMBED_SELFTEST=skip`, unsafe) serves every function unchecked. Tolerances are per kind and a package can only tighten them; every `selftest.json` field is bounds-checked. `/health` stays 200 but reports `degraded`, with the functions not served and the remaining limits. `doctor` lists the functions a `--max-tokens` value loads and keeps the records of functions a smaller `--max-tokens` did not load; `bench --buckets` times every function. Each load checks file sizes against the manifest and hashes `tokenizer.json` and the self-test files (0.01–0.03 s on an M4); the pinned revision loads only while its `manifest.json` hashes to the one pinned in this build (`doctor` reports it too). `manifest.json`, the self-test files, the state files and `models/current` are read only as regular files under a size cap far above their real size, so a FIFO, a device or a huge file there is an error. `models install` validates `--revision` and `--repo`, takes a lock so a second install waits, swaps the revision directory in one rename, reuses an installed revision only when its manifest matches the expected hash, stops a download that exceeds its declared size, hashes only regular files, and refuses `--runtime fake`; `models verify` reports the compiled models. The warm state records the package's manifest hash.

Requests. Texts over the limit are `400 context_length_exceeded`, never truncated; a text of more than the limit × 93 bytes (93 bytes is the tokenizer's longest token) cannot fit and is refused before it is tokenized, reported as having at least its bytes / 93 tokens. `/v1/embeddings`, and `embed_image` over MCP and `QUERY`, check the number of inputs and images against `--max-inputs` and `--max-images` before decoding any image; `embed_image` also checks each image's size from its base64 before decoding it. A request to a server that is still loading is `503` before parsing. Every output vector is L2-normalized on the host, at 768 dimensions as at the Matryoshka sizes. `/v1/models` has the `created` and `owned_by` fields of OpenAI's model object. `500` and `503` responses over HTTP (including MCP tool errors on `POST /mcp` and `/health` after a failed load, which reports the `reason`) keep their error code and use a generic message; the detail, which can name paths, goes to the server log. JSON with invalid UTF-8 in a string is `invalid_json` (a raw `QUERY /embed_text` body `invalid_utf8`). Empty token sequences, oversized vocabularies and negative token ids are errors, not traps, and vectors of very small or large values normalize. stdio input (`mcp`, `embed --stdin`, `tokenize --stdin`) is read in lines of at most `--max-body` bytes (MCP answers a longer message with `-32600`, the commands stop with `line_too_long`) and at most 16 MCP messages are in flight, so stdin cannot grow memory without bound.

HTTP. HTTP/1.1 with keep-alive and pipelining. `HEAD` responses carry the `GET` headers and no body. Requests with ambiguous framing (`Transfer-Encoding` together with `Content-Length`, any transfer coding but `chunked`, or `Content-Length` headers that differ) are `400` and close the connection. A request head must arrive within 60 s; a body may pause at most 60 s between bytes, however long it takes in total; a response must be sent within 60 s plus one second per 64 KiB, or the connection is closed, so a client that stops reading cannot hold a connection. At most `--max-connections` (default 64) connections are open; more are answered `503 too_many_connections` and closed. Searching for the end of a request head is linear for heads sent byte by byte.

Request bodies over 1 MiB share one budget of `--max-body` bytes (72 MiB by default) across all HTTP connections: each reserves its `Content-Length` before any of it is read and waits in arrival order while the budget is spent. The waiting connection does not read, so TCP flow control slows the client; a wait longer than the body idle timeout (60 s) is answered `503 body_budget_busy` with `Retry-After: 1`. Bodies up to 1 MiB never wait; a single text is usually far smaller, while a large batch of texts can exceed it and then shares the budget. A body is allocated once at its `Content-Length`, handed to the request without a copy and freed, returning its share, as soon as the request is parsed (`/v1/embeddings`) or handled (other routes). Buffered request bodies take at most 136 MiB at the defaults (72 MiB plus 64 connections × 1 MiB).

Images. The JPEG decoder (8-bit Huffman: baseline, extended sequential and progressive) reproduces libjpeg-turbo's output, which is what Hugging Face sees through PIL; other formats, and JPEG variants it does not handle, go through ImageIO. A JPEG streams into the resize row by row, with the EXIF orientation folded into the two resize passes, so the full-size image never exists: one image adds at most 3–4 MiB for a sequential JPEG of 12–40 MP and 232 MiB (4:4:4) / 118 MiB (4:2:0) for a progressive one of 40 MP (M4); images are limited to 40 megapixels. Hostile JPEGs are bounded: Huffman symbols beyond 8-bit precision and every bit count read are checked, so a crafted file is `400 image_decode_failed` instead of a crash of the whole server; a file has at most 100 scans, and a progressive scan that repeats or skips a step of the progression is refused, also as `400 image_decode_failed` and without handing the file to ImageIO. A sequential JPEG with a second scan after the one that held every component is refused (and goes to ImageIO), as libjpeg-turbo refuses it. `jpeg-fuzz`, a deterministic mutation fuzzer for the decoder, runs in the tests and in CI; `--flat-jpeg [--progressive]` writes test files for memory measurements and `--max-seconds` stops a decode that does not return.
